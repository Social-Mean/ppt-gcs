# 原生大小与位置字段的约束提交

`NativeFieldController` 在原生字段提交之前接管大小与位置变化。Enter、Tab 和 Shift+Tab 在键盘按下时进入。点击其他控件或画布时，在鼠标按下且焦点仍在字段内时进入。点击字段自身或其子窗口继续交给原生光标和选字操作。`Tick` 只清理失效的字段上下文。

鼠标路径由字段控制器自己的线程 `WH_MOUSE` 负责，在已识别字段的 `WM_SETFOCUS` 完成后安装。第二次人工回归证明 Office 在首次 `HC_NOREMOVE` 之后、`HC_ACTION` 之前已经提交，单纯等待消息移出队列仍然太晚。当前修复让两个入口共用前置处理，并缓存同一次按下的结果，避免重复队列预览再次求解或创建历史。拒绝后的松开预览不会提前解除配对；真实松开后下一次点击能够重新尝试。该补丁已在实际第10页点击空白、第11页拖动窗口边框中完成前置联动，并逐次通过一次原生撤销和重做；详细范围及尚待核实的重入离焦表现见 `validation-editing-entries.md`。

微软公开 [MouseProc 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/mouseproc) 将 `HC_NOREMOVE` 定义为尚未从队列取出的鼠标消息，并允许对已处理的非负代码返回非零以阻止目标窗口接收。插件只在自身 Office UI 线程、已识别的字段持有焦点时使用这条入口。已捕获字段先用缓存与 Win32 焦点定位，随后在写入保护下读取 COM 上下文，防止预查询泵入离焦事件后丢失字段。失焦、明确换上下文和 Dispose 时移除专属 hook，拒绝时保留对应松键配对。公开钩子语义不能代替实际 PowerPoint 的一步撤销/重做验收。

真实回归已经发现：PowerPoint 可以在 `WM_KILLFOCUS` 到达当前 UI 线程的 `WH_CALLWNDPROC` 前置回调之前提交驱动对象。因此该回调只核验结果、记录未被前置接管的变化并恢复曾拒绝的字段文本，绝不在其中补写跟随对象。将这种补写作为成功路径会把一次操作拆成两个撤销项。

Ribbon 宽高字段身份来自 PowerPoint 的公开 `CommandBars.GetScreentipMso("ShapeWidth")` / `ShapeHeight`，与焦点 `RICHEDIT60W` 的 MSAA 名称精确匹配。面板宽高名称使用公开 `GetLabelMso` 去除 Unicode Format 字符及末尾冒号后匹配，并严格限定在已实测的“设置形状格式/大小”分组和五级 Win32 窗口链。中文原生面板的位置字段必须同时匹配已实测的水平/垂直位置名称、相同窗口链及“设置形状格式/位置”MSAA 分组，并从该字段之后第一个名为“从”的组合框读取参考原点。未知控件继续只记录名称、祖先控件和纯数值。

原生字段焦点下，PowerPoint 的选择类型可以是形状或文字，均需读取实际 ShapeRange。宽高目标保持原生左上角。没有原生宽高比锁时，`NativeWidth` / `NativeHeight` 只锁定对应尺寸，另一尺寸仍可由约束决定；有原生宽高比锁时，按操作前比例推导另一尺寸，再作为完整目标求解。

2026-11-18 的真实 Ribbon 宽度上箭头采样找到新的前置候选：旧宽度为 140.031494 磅、显示 4.94 厘米；按一次上箭头后，`RICHEDIT60W` 向 `NetUICtrlNotifySink` 发送 `WM_NOTIFY / 1794` 时，缓冲已为 5 厘米，A 的几何仍为旧值，读取前后相同。随后 `WM_COMMAND / 768` 仍是旧几何，再之后才读到 141.732284 磅。全过程 `EM_GETMODIFY` 为 0，不能用普通输入的 dirty 标志判断微调请求，也不能把该行为猜成在原值上固定加 0.1 厘米。

该次只读记录器已在原生 Undo/Redo 检查前停用；一次 Undo 将 A 恢复到 140.031494 磅，一次 Redo 恢复到 141.732284 磅，B 保持 210 磅。实际日志和历史位于本机 `Sessions/native-spin-entry-probe-v2-20261118`。

随后独立的一次写入实验取得正面结果：真实上箭头将字段由 5 改为 5.1 厘米，在同一 `1794` 前置通知中各给 A、B 写一次宽度，卸载观察器后延时读取，两者都保持请求的 144.566925 磅，其他坐标和高度不变。切回画布后一次原生 Undo 同时恢复 A 的 141.732284 磅与 B 的 210 磅，一次 Redo 同时恢复目标值；没有双重递增或后续覆盖。证据为本机 `Sessions/native-spin-apply-once-20261118/native-history.json`，setter 计数各为 1，错误为空。

这证明的是独立原型中单个 Ribbon 宽度上箭头的成功路径，还未接入生产，也不证明冲突可取消。`1794` 是 `EN_SELCHANGE`，没有 veto 返回值；观察钩子不能在求解失败后阻止 Office 继续提交。用户随后确认 A/B 显示同宽，并澄清之前未看到 B 缩小是看错了；该单例的显示差异已经排除。

独立拒绝实验已经否定“吞字段通知并回填旧文本即可取消”的方案。在真实字段的 `DefSubclassProc` 上箭头处理栈内，捕获新 5.2 厘米／旧几何后，标准 subclass 抑制了该字段的 8 条通知，并且只回填一次旧精确值 `144.56692504882813 pt`。原处理返回时 A 仍已变成 147.401581 磅，B 保持 144.566925 磅；失焦及重新选中后依然如此，字段回填不能代表几何已拒绝。该实验没有写形状、创建 Undo 项或事后修复。两个 subclass 和观察钩子已移除，实验注册也已清理。证据位于本机 `Sessions/native-spin-reject-once-20261118`。生产实现不能采用这条被实测否定的取消路径。

顶层多选先对所有选中的约束对象共同求解，选中但没有约束的对象也纳入同一写回和回滚。未关联的独立约束组件不会阻止本次操作。成功路径先求解，再开启一个原生撤销项，写入并读回核对完整几何和本次连通组件的约束残差，然后允许原生控件继续提交相同数值。

单个或多个组内成员统一复用 `GroupChildNativeEdit` 和 `GroupChildEditPlan`。先写真实成员，读取 Office 实际计算的顶层组合边界，再求解组合外的关系。成员与跟随对象在同一事务内回滚，写回列表始终排除所有实际编辑的父组合，避免通过恢复父组合宽高缩放组内其他成员。

位置值允许负数，保留尺寸和另一轴。已分别实测“左上角”输入直接对应 COM Left/Top；水平、垂直“居中”原点分别增加半个幻灯片宽、高。因此水平“居中”输入 0 对应 `Left = SlideWidth / 2`，不是形状自身的中心对齐，不得减去对象半宽。每次数字提交都重新读取当前原点，避免原点组合框没有改变 RichEdit HWND 焦点时继续使用旧缓存。

原点组合框自身也是几何编辑入口：真实操作显示由左上角切换水平居中会在现有 Left 上增加半个幻灯片宽度，且有独立原生撤销项。当前数字输入支持不代表原点组合框切换已被接管，这个入口仍需独立实现和验证。多选水平方向已实测逐个设置 Left；完整的约束联动、其他方向与原生历史仍需正式回归。

单位保留字段获得焦点时的后缀；无后缀的数值或混合空字段使用用户区域设置。原生基线已确认多选混合位置直接输入裸数 8 时，按系统厘米处理，并将每个对象的 Left 设为同一绝对值，保留各自 Top 和宽度。支持 cm/mm/in/pt 及对应中文后缀。输入的显式后缀不能直接改变缓存的显示单位；成功 Enter 的松键阶段才读取原生格式化后的字段后缀，避免输入 mm 被 PowerPoint 转回 cm 后，下一次裸数误用 mm。NaN、Infinity、非数值和小于 1 磅的尺寸不会提交。

是否需要前置写回只依据只读 `EM_GETMODIFY`。原始返回 0 时保留原生无编辑行为。非零时即使最终文本与初始完全相同，仍按用户编辑处理。未知或失败的查询拒绝提交。原生基线中，140 磅显示 4.94 厘米，只聚焦离开仍为 140。重输 4.94 后修改标志为 -1，原生提交为约 140.031494 磅。位置字段实写且校验后，将已求解的坐标按当前单位回填给控件，并清除 RichEdit 修改标志。真实 PowerPoint 中已核验水平 Enter 和垂直 Tab 各自的一步原生撤销、重做及保存重开。

其他进程的点击不经过本 PPT 线程鼠标钩子。当前仅对已识别活动字段记录 `WM_NCACTIVATE(false)`、`WM_ACTIVATE(WA_INACTIVE)` 和 `WM_ACTIVATEAPP(false)` 的字段、修改标志、焦点、选中几何和关联范围，不在未经实测的失活消息里写回。离开 PowerPoint 的提交时序仍需单独验证。

字段上下文区分匹配、明确不同和暂时不可读。已识别字段的 COM getter 失败不能原生放行提交，也不能在生命周期检查时丢掉已知缓存；新字段只有成功识别之后的上下文捕获失败才拒绝输入，未知控件继续交给原生。布局读取绑定捕获的 DocumentWindow，前后校验文稿、窗口、幻灯片身份，写回前再次校验。

获得字段焦点时只读捕获实际所选根对象及其关系范围。未捕获到范围或上下文不可读时，失焦核验记录未知和空残差值，不能把空 seed 算成残差 0。失活日志在任何 COM 调用之前进入重入保护；若发生在写入过程中，只记录 Win32 窗口标量，不再嵌套读取完整布局。

冲突 Enter/Tab 被消费，供用户修改输入。点击外部时发生冲突，会同时消费本次鼠标按下和对应松开以保留字段焦点。若其他焦点变化仍触发失焦，则把曾拒绝的字段文本恢复为操作前实际对象尺寸的高精度显式 pt 值。不能用界面显示的两位小数恢复几何。多选原尺寸不相等时只能恢复混合空字段；该路径需要实测确认 Office 不继续提交缓存的旧值。

## 验证范围

纯测试覆盖单位、区域小数、非法数值、最小尺寸，以及宽高字段的求解锚点和连通组件。独立原型已验证单个宽度字段的 Enter 前置写回可将驱动对象和跟随对象放入一个原生撤销项；原型结果不能替代正式模块回归。

正式模块仍需逐项进行原生交互、一步撤销、重做、保存重开验证，尤其包括非客户区拖动窗口前提交、失焦冲突、高精度恢复、混合空字段、原生宽高比锁、多选额外对象和组内成员。尺寸微调箭头、不同样式的原生面板、位置原点组合框和多选位置尚未获得完整交互证据。组内文字 AutoSize 导致的边界变化需要单独处理。上述项目不能仅根据编译通过或程序回放宣布通过。
