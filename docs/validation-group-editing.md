# 组合内部编辑入口修复

日期：2026-11-17；版本：v0.6.2。主修复和最终补丁的真实鼠标复测通过，包括组合拖动、子成员选择与移动、双击进入文字编辑；原生历史及保存重开检查也通过。

## 原因与交互规则

原鼠标入口只在按下前 `HasChildShapeRange` 已经为 true 时让行。尚未进入组内选择时，`RangeFromPoint` 的命中会被 `TopLevel` 提升为受约束组合，随即重新选择组合并捕获鼠标，吞掉原本用于选择 A/B 的点击。延后到 4 DIP 才写入几何并不能恢复这个原生点击。

v0.6.1 曾尝试将已选组合内部输入直接交回 PPT，仅保留外框整体拖动。用户实测反馈“拖 AB 组合时，C 有时没有联动”。日志显示，内部放行既允许选中子成员，也允许 PowerPoint 原生移动整个组合，后者没有经过约束求解；另有真实命中组合但位于 COM 报告外接框之外的输入，被后续几何命中判断拒绝。这一版不能作为实际鼠标联动通过的证据。

v0.6.2 将组内点击和整组拖动作为同一候选手势处理。按下时保留 `RangeFromPoint` 的原始命中及其顶层组合，命中子成员时保留该精确成员，不立即改选子成员或写入几何；越过 4 DIP 拖动阈值后，选择顶层组合并沿用整体约束求解。正常松手且始终未越过阈值时，未选组合只选择父组合；已选组合则通过实际命中子成员的公共 `Select()` 进入组内选择，并再次验证其所属组合。缩放、取消、失焦和实际拖动结束均不触发这次子成员选择。单纯点击不启动几何撤销条目。

真实原生命中只要归属目标组合，就不再因超出 COM 外接框而漏接。原生空命中时，仍只允许已选组合有限的外框带；命中另一对象时不抢占。八个缩放点继续优先处理。已进入 `ChildShapeRange` 的输入、文字编辑和双击仍交给 PPT，未进行合成鼠标输入重放。

使用方式：先选中组合，再单击 A/B 进入组内编辑。退出组内编辑后，可从成员内部或外选框拖动整体，也可使用缩放点。

## 验证

- 完整构建与 302 项检查通过：48 项组合指针策略检查和 254 项既有检查。新检查覆盖真实组合命中超出报告边界、有限外框带、DPI、小组合、其它类型隔离，以及无拖动选择子成员和拖动、缩放、取消、非正常释放时的禁选条件。这些纯策略检查不等同于真实鼠标入口验收。
- 真实 PowerPoint 的 v0.6.2 程序化检查通过。私有测试文稿第一页面为 AB 组合与 C 的顶端对齐、同宽关系，第二页为无约束组合对照。
- 程序化分别选中 A/B，`ChildShapeRange` 均指向正确成员；B 的文字和 A 的填色可单独修改，其余捕获属性与约束保持。两项修改逐次原生 Undo/Redo/Undo 恢复。
- 初轮组合与 C 分别作为驱动，完成 Move 和 ResizeE 四组程序化轨迹，逐次核对原生 Undo/Redo、组成员、文字、原生属性、编号、约束 XML 和独立约束公式；共完成 14 次历史状态比较。
- 初轮保存并同进程重开后，组合结构、捕获属性和文字、几何、编号与关系保持。随后最终补丁的新进程重开结果见下文；未保存或关闭其它原文稿。

松手前以 COM `IUnknown` 身份和 Slide ID 核对所属窗口/页面；程序化轨迹也执行这一身份检查。初次复查发现 `DocumentWindow.HWND` 在当前接口不可用，已在鼠标复测前移除并重新构建、安装及执行完整程序化验证。

## 当前边界

约束仍作用于顶层组合外接框。原生编辑子成员若改变这个外接框，当前不会自动求解并带动 C；这条更新路径不在本次点击入口修复中。整体约束拖缩应在退出组内编辑后进行。嵌套组和多选组的完整物理交互也未在本轮穷举。
