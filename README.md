# PPT GCS

Windows 桌面 PowerPoint 的形状排版约束插件。支持自选图形、文本框、图片、SVG 图标、自由曲线和组合整体，提供 32 种布局约束、画布约束标记、原生可停靠的“约束”窗格、中键八向轮盘，以及约束新增、修改、启停、删除和下述已实现几何编辑入口的原生撤销/重做。功能区、轮盘和窗格使用 Office 图标资源。[编辑入口验证](docs/validation-editing-entries.md)

选中对象时，画布旁显示相关约束的图标、名称与细引导线。单击标记可高亮关系并选中参与对象。双击带参数的标记可在约束窗格修改数值，按 Enter 保存。右键标记可启用、停用或删除关系。功能区“画布标记”可切换“仅所选对象／显示全部／隐藏标记”。标记跟随拖动、缩放和滚动，编辑文字、打开轮盘或离开画布时隐藏。引导线与标记外的区域仍由 PowerPoint 处理，放映和导出使用原有幻灯片内容。验证范围见 [画布标记验证](docs/validation-canvas.md)。

约束窗格显示所选对象可移动的方向和尺寸状态。拖动受限时，限制本次操作的关系以橙色标出。新建或修改发生冲突时，窗格列出相关对象和具体约束，可选择停用后重新提交。停用和本次修改共用一步原生撤销。[冲突与可编辑方向验证](docs/validation-constraint-diagnostics.md)

受约束组合的点击和拖动先作为同一候选手势处理：超过拖动阈值后，从成员内部或组合外框移动整体，维持外部约束；正常松手且未拖动时，首次选择组合，已选组合则选择实际命中的子成员。进入组内选择后，成员可以单独移动、缩放，并按实际组合外接框传播外部约束；单击、双击进入文字编辑仍交给 PowerPoint。原有交互规则和历史验证见 [组合编辑修复](docs/validation-group-editing.md)，新增入口与边界见 [原生数值字段说明](docs/native-edit-fields.md)。

“固定宽高比”使用 PowerPoint 的“幻灯片大小”图标。“中心重合”使用指定的 `DiagramTargetInsertClassic` 内置图标，见 [图标验证](docs/validation-center-icon.md)。约束窗格保留独立停靠方式，窗格堆叠研究已结束，见 [窗格说明](docs/pane-integration.md)。

v0.5 将当时的 20 类约束接入功能区，并用逐像素透明层修复轮盘的紫色锯齿。该版本通过 232 项自动检查及 20 类入口的共享执行和原生历史检查。[v0.5 界面验证](docs/validation-ribbon-ui.md)

v0.4.2 补齐文本框选框外沿及首次边框拖动的约束接管；192 项自动检查通过，真实漏接证据与复测状态见 [边框修复记录](docs/validation-text-border.md)。每列四个的约束类型按钮及 Office 图标透明度/DPI 修复见 [v0.4.1 记录](docs/validation-ui.md)。

**v0.4 的程序化形状与图标检查通过。** 11 类代表对象的 44 次双向程序化轨迹及逐次原生 Undo/Redo、非矩形复制后新建关系、同进程和新进程保存重开均通过；25 个命令的内置图标映射已在 PowerPoint 进程内成功加载。新增异形对象的真实鼠标操作和图标显示效果尚未通过人工验收。范围、证据及限制见 [形状与内置图标验证](docs/validation-shapes.md)。

v0.3 的矩形约束、轮盘和窗格真实鼠标结果见 [v0.3 验证记录](docs/validation-v3.md) 与 [交互验收](artifacts/v3-interaction/acceptance.json)，更早记录保留在 [v0.2](docs/validation-v2.md) 和 [v0.1](docs/validation.md)。这些历史结果不代替 v0.4 新增形状的真实鼠标验收。几何日志记录实际写回采样，不代表渲染 FPS。

## 构建与安装

当前仅面向 **Windows + 64 位桌面 PowerPoint**。开发机需要 Visual Studio 的 MSBuild、Roslyn 编译器、C++ x64 工具、Windows SDK、ATL，以及已安装的 Microsoft Office / Office PIA。项目使用 .NET Framework 4.8 原生 COM 加载项，不依赖 VSTO 项目模板或 .NET SDK。

关闭 PowerPoint 后，在项目根目录的 64 位 PowerShell 中运行：

```powershell
.\scripts\Build.ps1
.\scripts\Install.ps1
```

`Build.ps1` 编译托管加载项、核心库和原生 ATL 窗格宿主，并运行 551 项自动检查，产物位于 `bin/`。首次构建从 NuGet 恢复固定版本 `Microsoft.NETFramework.ReferenceAssemblies 1.0.3` 和 `MathNet.Numerics 5.0.0`，缓存于 `.packages/`。MathNet 使用 MIT 许可证。官方 Extensibility 和 Office PIA 的 COM 接口元数据由编译器嵌入插件。

`Install.ps1` 注册当前用户的加载项和 `PptGcs.ConstraintPaneHost` 原生控件，不需要管理员权限。重新打开 PowerPoint 后应出现 **PPT GCS** 功能区。注册指向本项目的 DLL；移动项目目录后需重新运行安装脚本。重新构建前请关闭 PowerPoint，避免加载中的 DLL 被占用。

也可以用 Visual Studio 打开 `PptGcs.sln` 编辑源码。安装脚本使用的统一输出目录由 `Build.ps1` 生成。

## 建立与编辑约束

**PPT GCS** 选项卡提供对齐、尺寸、间距、偏移与对称，以及相对幻灯片和容器的约束。11 类无参数约束直接使用当前选择创建。21 类数值约束打开参数编辑器，确认后才写入关系。

1. 在同一页选中至少两个支持的未旋转对象，点击 **左对齐**、**顶端对齐**、**同宽** 或 **同高**。可以在不同类型之间建立关系，例如椭圆与图片同宽。
2. 建立等间距时至少选中三个对象，点击 **水平等间距** 或 **垂直等间距**。建立时按对应坐标排序，之后始终按这个已记录的成员顺序计算。
3. 从对象可命中的轮廓或内部拖动可以移动它；先选中一个对象，再拖动原生选择框的八个缩放点，可以调整大小。拖动西侧、北侧或角点时，以相对一侧为锚点计算新几何。操作组合整体时先退出组内编辑；选中组内成员后，也可以单独移动或缩放成员。
4. 同宽或同高关系会传播对应尺寸。位置和间距约束根据更新后的尺寸重新求解，其余位置尽量少移动。
5. 选中关系中的对象，点击 **移除选中对象的约束** 可移除相关关系；**状态** 显示当前载入情况和日志路径。
6. **新建六组演示** 会生成使用新存储的基础测试文稿，每页写有操作说明，也可打开 [v0.3 交互测试文稿](artifacts/v3-validation/layout-v3.pptx)。

全部布局约束按对象的外接框计算。X、Y 分别指外接框的左侧、顶部坐标；同宽、同高和间距也使用外接框，三角形、椭圆等形状的实际曲线轮廓不参与求解。等间距的数值没有固定，也没有固定首尾：拖动目标按编辑位置确定，其他位置采用最小平方位移解。

间距是**有符号的外接框边缘间距**，允许变为负数而出现重叠。等间距的数值可以变化；固定间距还要求等于输入的值。拖动过程中不重新排序成员。固定位置表示左侧 X 和顶部 Y 不变，仍允许兼容的尺寸编辑；宽高比为“宽 / 高”；偏移为第二个对象相对第一个对象的 X/Y 差；轴对称使两个等尺寸外接框关于输入坐标轴对称，箭头、图片等内部内容的方向不会翻转。坐标和尺寸单位为磅（pt）。

文本框内部的单击、双击及拖动选字交给 PowerPoint 原生处理；沿边框起拖可以直接移动文本框，保持布局约束。选中的边框支持外接框内外约 6 DIP 的命中带；未选中对象必须由 PowerPoint 命中该对象才接管，命中其他覆盖对象时不抢占。八方向缩放继续由 GCS 维持布局关系。已有文字编辑状态下，形状内部也保留原生文字输入。

## 幻灯片与容器

选中一个或多个对象，从 **PPT GCS → 相对幻灯片** 选边距或居中。要以页面中的某个对象为参考，从 **相对容器** 打开对应类型，在窗格的 **参照容器** 中从所选对象里指定它。其余所选对象使用同一条关系。两种参考都支持左、右、上、下边距以及水平、垂直居中。

边距以磅（pt）输入，0 表示边缘对齐，正值朝参考框内侧，负值朝外。居中的偏移量为 0 时中心对齐，正值向右或向下。对象同时约束到同一参考框、同一轴的两条不同位置时，宽度或高度随参考框变化，例如同时保留左、右内边距。容器可以嵌套，循环引用会提示冲突。

通过 **PPT GCS → 幻灯片尺寸…** 输入宽高并应用到全部幻灯片。插件先检查所有受约束的页，再修改 PowerPoint 页面尺寸和对象几何，两者共用一步原生撤销和重做。PowerPoint 自带的 **设计 → 幻灯片大小** 直接运行其内置缩放，保持约束的页面重排入口是 **PPT GCS → 幻灯片尺寸…**。[页面与容器约束验证](docs/validation-reference-constraints.md)

## 约束窗格

点击 **PPT GCS → 约束窗格** 打开标题为 **约束** 的右侧可停靠窗格。它是独立 Office 自定义任务窗格，不改写内置选择窗格。对象列表和关系列表支持“当前页全部 / 仅所选对象”过滤，点击对象或关系会同步选中画布成员。

关系列表显示类型、成员顺序、参数及已满足、未满足、已禁用或对象缺失状态。可以创建关系、修改数值、启用/停用，以及只删除选中的一条关系。等间距保持一条多成员关系。Ribbon、窗格和轮盘共用同一套命令，提交前先求解，冲突时保持原状态。

“新增…”中的类型选择是 **4 列、8 行** 的按钮区，按类型顺序从左到右逐行排列。按钮显示图标与名称，选择数量不足或包含不支持的对象时置灰。修改已有关系时锁定类型。窄窗格可横向滚动按钮区。

## 中键轮盘

先选中对象，再在幻灯片画布中按住中键，向目标扇区移动，松开确认；回到中心释放或按 Esc 取消。八个固定扇区为左对齐、顶端对齐、同宽、同高、水平等间距、垂直等间距、更多约束、约束窗格。

对象数量不足的命令置灰，预览不写入文稿，确认后才创建关系。“更多约束”打开窗格编辑器，数值约束在窗格中输入。中键仅在 PowerPoint 幻灯片画布接管，滚轮滚动仍交给 PowerPoint。

轮盘使用逐像素 alpha 的原生分层窗口呈现，曲线、文字、图标与预览都保留透明度；不再使用洋红色透明键。它保持不激活和鼠标穿透，原画布继续持有拖动捕获。

## Office 内置图标

功能区通常通过 `imageMso` 引用 Office 图标，窗格和轮盘通过 `CommandBars.GetImageMso` 从当前 PowerPoint 获取同一套资源。对齐、居中、等间距使用相应的内置命令图标；同宽、同高借用 Office 的平均分布列宽/行高图标。图标保留文字标签，不改变约束含义。

固定宽高比映射到 `PowerPointPageSetup`（幻灯片大小），中心重合映射到 `DiagramTargetInsertClassic`。功能区直接使用 `imageMso`，窗格和轮盘通过 `GetImageMso` 按需要的尺寸取得原生图像；保留原始透明度并缓存复用。图标仍执行插件原有约束命令。

托管图像按 Office 实际返回的 straight alpha 格式保存，避免半透明边缘被错误解释。窗格采用 16、轮盘采用 32 逻辑像素，按宿主实际 DPI 获取对应设备像素尺寸并原样绘制；DPI 改变后重新取图，不在绘制时访问 Office。

## 适用范围与复制

当前实现的几何联动入口包括：

- 幻灯片画布上的普通鼠标移动、八方向缩放，以及选中形状后的方向键微移和 Ctrl + 方向键微移。文字编辑中的方向键仍用于移动光标。
- 在 PowerPoint 原生宽度、高度、水平位置或垂直位置数值框中输入数值，通过 Enter、Tab，或在同一 PowerPoint 窗口内点击其他位置提交。位置字段支持读取当前“从”为“左上角”或“居中”的参考原点。
- 顶层对象多选移动和键盘微移。选区可以同时包含受约束对象和未受约束对象；零宽或零高的线条可以作为未受约束成员随同移动，并保留原有尺寸。
- 组合内部成员的移动、缩放，以及由此产生的组合外接框变化对外部约束的传播。

上述是实现范围，各入口的实际验证及边界见 [原生数值字段说明](docs/native-edit-fields.md)。鼠标操作时按住 Ctrl、Alt 或 Shift 仍使用 PowerPoint 原生手势，该鼠标手势不会由插件维持约束。

以下入口尚未支持约束联动：原生数值框中的 ↑/↓ 和增减按钮；切换位置字段“从”的下拉选项；组内文字自动调整大小引起的组合外接框变化；输入数值后直接切换到其他应用所触发的提交。**离开 PowerPoint 前，请先按 Enter 或 Tab 提交数值。** 正常文字输入、选字和光标操作继续使用 PowerPoint 原生编辑。

复制已标记的对象时，副本会自动获得新的唯一编号，不继承原件的约束；可以选中副本建立独立关系。支持同页复制、复制副本，以及跨页、跨文稿粘贴。原件编号与已有约束保持不变，详见 [复制编号修复与验证](docs/copy-identity-validation.md)。v0.4 另有非矩形副本新建关系及原生 Undo/Redo 检查，见 [形状验证](docs/validation-shapes.md)。

原生撤销/重做覆盖约束新增、修改、启停、删除，以及上述已实现入口中的受约束几何编辑。此前仅更新 CustomXMLParts 导致的元数据历史缺口已修复；“复制 → 新建副本关系 → 撤销关系 → 撤销复制 → 重做复制 → 重做关系”链也已在实际 PowerPoint 中通过，见 [复制历史报告](artifacts/v3-copy-validation/latest.json)。历史失败证据仍保留。

当前可建立约束的对象包括同页、未旋转的顶层自选图形（椭圆、三角形、圆角矩形、菱形、箭头等）、文本框、图片及链接图片、SVG 图形及链接图形、自由曲线，以及组合整体。建立约束的对象宽高至少为 1 pt；组合内部成员通过其所在组合参与外部关系。线条、连接符、表格、图表、SmartArt、占位符和旋转对象暂不能建立布局约束，窗格会显示原因。黄色调节点、编辑顶点和路径编辑不属于布局手势。相切曲线、三维配合、不重叠不等式及完整自由度诊断不在当前范围；已有关系满足不意味着对象已无移动自由度。

## 数据与验证

- `PptGcs.Core`：不依赖 Office 的约束模型、XML 校验、比例尺寸组，以及使用 MathNet 的线性位置约束求解。几何编辑只传播到相关连通分量，参数修改可以进行无驱动对象的归一化求解。
- `PptGcs.AddIn`：PowerPoint COM 接入、功能区、鼠标移动与八方向缩放、原生 Undo 边界及文档存储。
- `ConstraintCommands` 提供三个 UI 入口共用的原子命令；`NativeConstraintStore` 将权威 XML 用 UTF-8 转大写 HEX 存入演示文稿 `PPTGCS_CONSTRAINTS` 标签，随几何进入原生历史。XML 上限为 1 MiB UTF-8，语义命名空间仍为 `urn:ppt-gcs:v2`。
- `ShapeIdentityManager` 用文稿令牌、Slide ID 和原生 Shape ID 记录编号归属；复制后的对象分配新 GUID，原件的关系引用不变。编号处理只更新标签，不改写几何或约束 XML。
- `PptGcs.PaneHost` 为原生 ATL ActiveX 宿主，承载托管 WinForms 窗格内容。
- v0.3 不保留旧 `CustomXMLParts` 或 v0.1 的运行时兼容路径，不自动迁移。当前会话的用户文稿已在备份后一次性保留全部 14 条原关系并另存为新存储工作副本；私人文稿和备份不进入仓库。旧文稿与验证记录作为历史证据保留。
- 日志仍写入 `%LOCALAPPDATA%/PptGcs/layout-v2.log`，当前验收见 [形状与图标验证](docs/validation-shapes.md)，历史 v0.3 验收见 [验证记录](docs/validation-v3.md)。

当前程序化验收脚本需通过 Windows PowerShell 5.1 运行：`TestV3Commands.ps1 -CheckPane` 检查事务和窗格，`TestV3Constraints.ps1` 检查 20 类关系，`TestV3CopyHistory.ps1` 检查复制及新关系的连续历史，`TestV3Persistence.ps1` 以 Capture/Verify 两阶段核对新进程重开。命令和复制脚本只创建和关闭自己的测试文稿；持久化脚本只读当前指定的测试文稿，重启由调用者执行。

`TestShapeSupport.ps1` 自建 11 类混合对象文稿，检查双向程序化轨迹、逐次历史、非矩形复制和同进程重开；`-VerifyReopenedDirectory <运行目录>` 只读核对已在新 PowerPoint 进程中打开的同一测试文稿。物理鼠标验收仍需单独进行。

旧 `TestLayoutDocument.ps1` 和 `VerifyLayoutEvidence.py` 对应历史六类约束证据，不能作为当前版本全部功能的通过证明。

## 卸载

关闭 PowerPoint 后运行：

```powershell
.\scripts\Uninstall.ps1
```

脚本删除插件和原生窗格宿主的当前用户注册项。PPT 文件与其中的约束数据保留；未加载插件时，对象仍按普通 PowerPoint 形状显示。
